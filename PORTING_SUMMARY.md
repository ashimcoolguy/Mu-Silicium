# Хроника портирования Mu-Silicium UEFI на Realme GT Master Edition (lunaa)

Данный документ содержит полное техническое описание процесса портирования прошивки **Mu-Silicium (Project Silicium)** на смартфон **Realme GT Master Edition** (`lunaa`), включая анализ архитектуры, выявленные проблемы и принятые инженерные решения.

---

## 1. Спецификация целевого устройства

* **Модель:** Realme GT Master Edition (`lunaa` / RMX3360 / RMX3363)
* **Чипсет (SoC):** Qualcomm Snapdragon 778G 5G (SM7325 / кодовая база Kodiak / Yupik)
* **Архитектура CPU:** 8 ядер Kryo 670 (1x Cortex-A78 @ 2.4 ГГц + 3x Cortex-A78 @ 2.2 ГГц + 4x Cortex-A55 @ 1.9 ГГц)
* **Графика (GPU):** Adreno 642L
* **Дисплей:** Super AMOLED 1080x2400 (32 bpp, частота 120 Гц)
  - Адрес кадрового буфера (SimpleFB): `0xE1000000` (размер 36 МБ)
* **Хранилище:** UFS 2.2 (LUN0 объемом 235.1 ГБ содержит GPT с разделами `super`, `userdata` и др.; LUN1–LUN5 содержат служебные разделы xbl, modem, tz, hyp)
* **Управление питанием / кнопки:** PMIC через шину SPMI

## 3. Пройденные технические сложности и решения

### 3.1. Окружение сборки на Arch Linux
* **Проблема:** При запуске `stuart_update` NuGet Mono падал с ошибкой скачивания зависимостей NASM.
* **Решение:** В `Mu_Basecore/BaseTools/Bin/nasm_ext_dep.yaml` область зависимости изменена с `edk2-build` на `x86-build`, что позволило использовать системный компилятор `nasm`.

### 3.2. Крах на этапе DXE Core (черный экран / bootloop)
При первых запусках устройство уходило в мгновенную перезагрузку до инициализации экрана. Были локализованы две независимые причины:

1. **Конфликт `TzDxeLA.efi` (TrustZone):**
   - На смартфонах BBK (Realme/Oppo/OnePlus) стоковый загрузчик (XBL/ABL) блокирует и переводит TrustZone в защищенный режим до передачи управления стороннему коду.
   - Попытка драйвера `TzDxeLA.efi` повторно инициализировать контекст TZ вызывала аппаратный сброс процессора.
   - **Решение:** Драйвер отключен (`#INF`) в `APRIORI.inc` и `DXE.inc`.

2. **Нехватка памяти DXE Core Heap:**
   - После отключения `TzDxeLA` возник краш `AllocatePoolPages: Failed to allocate pages` в `DxeMain.c` (строка 581) из-за переполнения начального пула памяти (`0x9C700000`, 49 МБ).
   - **Решение:** В `Platforms/Realme/lunaaPkg/Library/MemoryMapLib/MemoryMapLib.c` блок памяти `0xA0000000` (256 МБ) переведен из типа `Reserv` в `Conv` (`EfiConventionalMemory`), предоставив DXE Core достаточный пул оперативной памяти.

### 3.3. Настройка GOP и кадрового буфера SimpleFB
* В `MemoryMapLib.c` выделен диапазон `{"Display Reserved", 0xE1000000, 0x02400000, AddMem, MEM_RES, SYS_MEM_CAP, Reserv, WRITE_THROUGH_XN}`.
* В `lunaa.dsc` прописаны PCDs экрана:
  - `PcdFrameBufferWidth = 1080`
  - `PcdFrameBufferHeight = 2400`
  - `PcdFrameBufferColorDepth = 32`
* Дисплей корректно отображает графический логотип и текстовое меню Boot Manager.

### 3.4. Аппаратные кнопки (Финальное решение)

#### Исходная проблема:
- Физическая кнопка Vol+ отправляла сканкод вниз (`SCAN_DOWN`), а кнопка Vol- — сканкод вверх (`SCAN_UP`).
- Кнопка Power отправляла вендорный сканкод Qualcomm `0x0102`, который не воспринимался стандартными приложениями UEFI как нажатие Enter.

#### Архитектурное решение:
Вместо изменения исходного кода EDK2 (`BootManagerMenuApp`), что нарушает стандарт UEFI и ломает ввод в других загрузчиках (GRUB, Windows Boot Manager, EFI Shell), исправление реализовано прямо на уровне аппаратного драйвера `ButtonsDxe.efi`.

#### Бинарный патч `ButtonsDxe.efi`:
Драйвер `Binaries/lunaa/QcomPkg/Drivers/ButtonsDxe/ButtonsDxe.efi` пропатчен в кодовой секции ARM64:
1. **Инверсия кнопок громкости:**
   - Смещение `0x6548`: инструкция `cbz w12, 0x655c` заменена на `cbz w13, 0x655c` (кнопка Vol+ отправляет `SCAN_UP = 0x0001`).
   - Смещение `0x655c`: инструкция `cbz w13, 0x65b4` заменена на `cbz w12, 0x65b4` (кнопка Vol- отправляет `SCAN_DOWN = 0x0002`).
2. **Кнопка Power (Confirm / Enter):**
   - Смещение `0x65dc`: `mov w8, #0x102` заменено на `mov w8, #0x0d` (`CHAR_CARRIAGE_RETURN` / `\r`).
   - Смещение `0x65e0`: инструкция перехода `b 0x6570` перенаправлена на `b 0x65bc` для прямой записи кода `\r` в поле `UnicodeChar` структуры `EFI_INPUT_KEY`.
3. **Результат:**
   - Драйвер нативно генерирует стандартные UEFI-события ввода.
   - Исходный код EDK2 (`BootManagerMenuApp` и `Boot-Manager.patch`) остался 100% чистым и соответствующим апстриму.

### 3.5. Режим USB Mass Storage

#### Безопасность разметки UFS:
В режиме Mass Storage экспортируется исключительно LUN 0 (`gEfiUfsLU0Guid`, 235.1 ГБ), на котором расположены Android-разделы и пользовательские данные. Доступ к служебным LUN 1–5 (xbl, modem, tz, hyp) намеренно закрыт: это предотвращает случайное повреждение критически важных разделов хост-системой (например, автоинициализацией дисков в Windows).

#### Особенность работы с хостом Linux:
Из-за специфики обработки команды SCSI `READ CAPACITY 16` в Qualcomm `UsbMsdDxe`, хостовое ядро Linux требует передачи квирка при загрузке модуля:
```bash
sudo rmmod uas usb_storage 2>/dev/null
sudo modprobe usb-storage quirks=05c6:f000:k
```
После этого диск и все разделы GPT монтируются штатно.

### 3.6. Интеграция ACPI
В субмодуле `Silicium-ACPI` создан файл `Platforms/Realme/lunaa/AcpiTables.inf`, ссылающийся на таблицы базовой платформы Kodiak (`APIC`, `CSRT`, `DBG2`, `DSDT_Minimal`, `FACP`, `GTDT`, `IORT`, `MCFG`, `PPTT`, `SPCR`, `SSDT`).

## 5. Инструкция по сборке и запуску

### Сборка релизного образа UEFI:
```bash
# В корне репозитория с активированным .venv:
./.venv/bin/python3 build_uefi.py -d lunaa -r RELEASE
```
Результат сборки: файл `Mu-lunaa.img` (размер ~1.6 МБ).

### Запуск на устройстве:
1. Перевести смартфон в режим Fastboot (`adb reboot bootloader` или зажать Vol- + Power).
2. Запустить образ без прошивки в память:
```bash
fastboot boot Mu-lunaa.img
```
*Устройство отобразит логотип Silicium и загрузится в меню Boot Manager.*

## 6. Важные замечания для локальной разработки

1. **Бинарники прошивки (`Binaries/lunaa`):**
   - Папка `Binaries/lunaa/` (включая пропатченный бинарник `ButtonsDxe.efi`) находится в субмодуле `Binaries` и не коммитится в основной репозиторий `Mu-Silicium`.
   - **Не выполняйте `git clean -fdx`**, чтобы не стереть извлеченные драйверы. Рекомендуется иметь резервную копию этой папки.
2. **ACPI (`Silicium-ACPI`):**
   - Файл `AcpiTables.inf` хранится в субмодуле `Silicium-ACPI` (ветка `lunaa`).
